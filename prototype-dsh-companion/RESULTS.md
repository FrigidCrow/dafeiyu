# 第一轮 DSH 原型结果

日期：2026-10-26（Asia/Tokyo）。保留分支：`codex/prototype-dsh-companion`。

**可继续 DSH 验证，宿主与治理有条件通过，真实模型未运行。** 在单条虚构记忆、串行操作、本地模拟 provider 的范围内，管理页状态能够控制真实 DSH 请求；人工纠正、遗忘和正常进程重启后的状态一致。本轮不能据此认定真实模型行为、完整产品验收或完整 MVP 已完成。

[lifecycle.json](evidence/lifecycle.json) 保存 23 次操作的轨迹、最终状态和完整请求：20 次请求到达模拟 provider，其中 3 次为原生摘要请求；12 项检查全部为真。覆盖记忆形成、原生工具读取、压缩、人格更新后立即压缩、纠正、遗忘、新会话、子进程重启和旧档案反例。最终已结算模拟用量为 2,000。

[budget.json](evidence/budget.json) 保存 18 次操作及 10 项全部为真的检查。共有 8 次请求到达模拟 provider，其中 7 次各报告 100 Token，另一次连接中断缺失 usage；最终已结算 700、保留未知用量预留 200。预算拒绝后请求未触达 provider，重启后预留仍在。摘要拒绝依据 `budget-denied` 审计和请求计数，而不是仅凭压缩错误文案。

[stale-job.json](evidence/stale-job.json) 记录“候选捕获版本 1 → 人工遗忘成为版本 2 → 候选尝试提交”。候选实际经过与 `remember_sample` 相同的 `commitCandidate` 写入入口，得到 `memory-write-refused`；重启和受控读取后仍保持遗忘。这是可控的异步交错验证，不是线程并发或真实后台模型整理验证。

## 实际适配与发现

陪伴状态使用 DSH StorageDomain 的单条聚合记录。纠正或遗忘在同一次更新中提交版本、锁定、来源撤销、会话代次和 `sessionId=null`，随后通过 DSH 创建新会话；鱼的身份不变，旧会话仅留作档案。模型工具只返回当前允许的值，不将原生历史窗口无条件送回模型。

这是一种粗粒度的安全策略：每次纠正或遗忘会丢失旧会话的短期上下文。已证明本轮样例不会重新带入旧值，尚未证明这种中断对长期陪伴体验可以接受，也未验证保留无关上下文的细粒度治理。

原生手动压缩直接使用已存的 system 消息，可能错过刚从页面保存的人格。当前只继承 `BasicCompactionEngine` 的 `summarize` 钩子，将摘要输入的 system 替换为最新有效状态，并在完成时核对状态版本；原生范围选择、执行与压缩事务继续复用。摘要指令仍为默认的 coding 模板，没有完成陪伴摘要模板或真实总结质量验证。

早期方案曾在空闲会话直接追加替换 system 事件：内存接受，但持久日志恢复时被判为损坏。失败原件保存在 [idle-system-edit-session.v4.jsonl](evidence/failures/idle-system-edit-session.v4.jsonl)。最终实现已弃用该路径；这个反例说明“当场能运行”不能替代恢复验收。

空会话压缩返回 `null`，短会话也可能因没有有效范围或不能缩短而失败，不能记为成功。原生压缩可能将内部预算异常包装成通用错误，因此必须结合审计与 provider 触达记录定位。

## 结论的边界

- 每次请求固定预留 200、成功 usage 固定为 100，验证的是门禁控制流程，不是真实计费上限。未知 usage 保留占用；没有读取服务商余额。未挂载真实自动重试，已验证手工重试仍受门禁约束。
- 管理操作与对话串行执行。未验证线程并发、生成中的撤销、在途取消、发送前复核、突然崩溃或 Mac 系统重启。现有恢复证据是 DSH 子进程正常关闭后的真实重启。
- 仅验证一条样本记忆及受控精读；FTS 未启用，未验证语义召回、引用快照、Spill、备份恢复或清除原文。旧档案保留不等于已经擦除。
- 自动整理演练读取允许状态及检查候选提交；没有真实模型抽取、后台调度、中文长期记忆质量或自然表达验收。
- QQ 收发、B站发现、主动分享、真实账号与外部发送均未运行。

## 复现与下一步

按 [README.md](README.md) 使用 Node.js ≥24.9.0，执行 `npm ci --ignore-scripts`、`npm run prototype`，默认打开 `http://127.0.0.1:4317`。状态写入明显标识的 scratch 目录；双击 HTML 仅运行纯内存演示。

运行版本为锁文件中的 DSH npm 包 `0.2.1-rc.3` 与 Cordis `4.0.5`。先前[官方源码研究](context/research/memory/dsh-native-memory.md)固定在 `22ddee3792402c3e70ec5f86a63c3e3e895a2f60`；源码支持证据不等同于本次发布包的运行结果。

正式设计最小影响是保留受控来源入口、当前有效状态、候选提交时的版本检查和覆盖摘要请求的预算门禁；会话轮换目前只是原型适配，不新增 accepted ADR。下一步优先用真实模型检验人格与中文摘要、实际 usage 及关系连续性，再处理在途治理与故障恢复；这些通过后再扩展 QQ 与 B站整链。现有证据足以继续 DSH 路线，没有依据在本轮直接切换宿主。
