# 复用既有 Harness，优先验证 DSH

本项目选择复用已有 Harness 作为智能体执行底座，优先验证 DeepSeek Harness（DSH）。使用者选择这条路线的主要理由是继承既有能力，避免自行开发 Harness；自研重点是可自定义人格、可管理记忆、外部经历、主动陪伴、QQ 接入与统一管理界面。

业务协调和适配代码应调用宿主已有的智能体循环、模型与工具执行、会话等能力。新增一套并行运行时会增加维护和一致性成本，偏离这项选择；对既有能力不足的部分，应先用具体需求和验证结果说明，再补充业务机制。

本记录接受的是复用策略与 DSH 优先的验证顺序，不代表 DSH 的实际兼容性已经通过验证，也不代表最终宿主已锁定。AstrBot 保留为候选；现有架构中的独立 SQLite、具体调度适配、部署方式等仍是待验证提案，不因本记录而自动被接受。

依据：使用者在[产品定义讨论第 1 轮](../design/product-discussion.md)中的明确说明。已有固定源码研究见 [DSH 运行结构证据](../../architecture/evidence/dsh-runtime.md)，其证据不等于实机验收。
