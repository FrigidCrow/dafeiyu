# 大肥鱼产品定义

更新：2026-10-26（Asia/Tokyo）。状态：访谈中的产品行为决定已全部答复，本文汇总这些决定，供整体核对共同理解；不是运行验收报告，也不是已发布的实施规格。逐轮依据见 [讨论记录](product-discussion.md)。

## 要做的产品

先在使用者自己的 Mac 上运行一条大肥鱼，通过普通 QQ 好友身份相处。它有可自定义的人格与关系定位，能延续共同经历，自主发现 B站内容，并在合适的时候主动联系；使用者通过一个统一的网页管理人格、记忆、活动和预算。稳定后再迁往服务器。

自然表达、关系连续、真实外部经历与主动联系共同构成体验，不能只做好其中一项就宣称完成整个产品。

## 已确认的决定

| 方面 | 确定的产品行为 |
| --- | --- |
| 使用范围 | 当前单人使用、同时一条鱼；可以保存多份人格模板。 |
| 人格与关系 | 模板可编辑，不固定为朋友、恋人或宠物。核心人格由使用者设定；兴趣与表达习惯可以成长，核心人格改变须经确认。 |
| 修改与新建 | 修改当前角色延续关系与记忆；创建新角色从独立记忆开始，不自动继承旧角色经历。 |
| 表达 | 接近自然的人际聊天，避免客服腔和机械总结。允许对话自然结束，不强制每条都接话或追问；明确问题应正常回答。 |
| 自动记忆 | 自动整理明确事实、偏好和真实共同经历。推断单独标注；人工纠正优先，不自动改写核心人格。 |
| 档案与遗忘 | 默认保留原文供本人回看；要求遗忘的内容不再用于回答、回忆或整理，也不能从旧来源重新记住。另提供清除对应原文的操作。 |
| QQ 管理 | 可以在 QQ 中自然表达“记住”“改错”“以后别提”，管理页展示处理结果；核心人格变更和批量删除在管理页确认。 |
| 外部经历 | 能自行发现内容，不依赖逐条投喂链接。首版覆盖有字幕或充分文字材料、能够可靠理解的 B站内容；表达的经历与观点须与实际取得的材料相符。 |
| 主动联系 | 间隔、频率和安静时段可设置。未回复后仍可因新的、有意思的内容再次联系；不催促、不连续追问，连续未回复时降低频率。 |
| 统一管理 | 一个网页集中查看和操作人格、日记、近况、记忆及人工修订、活动、Token 用量和剩余情况。 |
| 预算 | 预算可调整，后台按剩余额度活动；接近上限先减少或停止后台活动、保留聊天额度。总预算达到上限停止发起新的付费请求，并提示调整，不自动透支。 |
| 技术路线 | 复用已有 Harness，优先验证 DSH；自研重点为陪伴能力和统一管理。AstrBot 保留为备选，最终宿主与记忆引擎尚未锁定。 |
| 交付方式 | 先 Mac 后服务器，目标是统一安装、配置和管理，避免使用者手工拼接一组独立插件。 |

“以后别提”按本轮已确认的遗忘语义处理，不默认等同于清除聊天原文；遇到含糊或超出单条记忆的操作，须在执行前明确对象与范围。

## 后续规格需要保留的边界

- 一站式是交付与管理体验目标，不等于底层只能存在一个进程。QQ 接入等依赖如何打包、启动和维护，需要 Mac 实机验证。
- 自主发现目前覆盖浏览和理解，不从中推导点赞、评论、关注或向其他人发送消息的授权。是否读取登录后的推荐首页仍属技术与后续范围评估。
- “已用 Token”“产品剩余预算”“服务商账户余额”“当前上下文容量”分别展示；拿不到真实数据时说明未知或更新时间，不合成一个精确的剩余 Token 数字。
- 遗忘需要覆盖当前上下文、派生摘要、后台整理、重启后的历史读取；具体清理以实际处理范围为准，不宣称撤回 QQ 消息或清除所有外部副本。
- 数值默认值、表达样例、记忆整理节奏和界面布局在原型中细化。管理页可分别设置“暂停主动活动”和“停止全部运行”，这仍是界面提议，不冒充本轮新增的用户决定。

## 用于后续验证的相处场景

下列是从已确认行为导出的验收场景，目前均未运行；自然程度最终需要使用者试聊判断。

1. **聊天与连续性**：在 QQ 正常交流，隔一段时间再次聊同一件事时能自然接续；“嗯嗯”等收尾不触发机械追问。
2. **人格与模板**：修改当前人格后保留相处记忆；创建新角色时不泄漏旧角色的相处经历；核心人格不被自动整理改写。
3. **纠正与遗忘**：先形成一条记忆，再在 QQ 或管理页纠正、遗忘；后续聊天、后台整理和重启后都遵守结果。档案仍可由本人查看；清除原文另行验证。
4. **真实外部经历**：没有逐条发送链接时，它取得并理解一份可读取的 B站材料，在日记或分享中留下可核对的来源，不声称看懂没有取得的画面。
5. **主动与不打扰**：遇到值得分享的新内容时主动联系；未回复时不催促，后续新内容受间隔、安静时段和降频规则约束。
6. **统一管理与预算**：从管理页调整设置能影响实际运行；后台和聊天用量均可追踪，达到预算上限后不再发起新的付费请求。

## 下一步：DSH 最小技术验证

先证明核心能力能连通：QQ 私聊进入 DSH，带人格与允许使用的记忆生成回复；纠正或遗忘在下一次交流中生效；后台取得一份真实 B站材料，在规则与预算允许时主动分享；管理页能看见并改变这些状态。

验证应复用 DSH 的执行、会话和上下文机制，避免另写一套 Harness。模拟消息可用于开发，但不能代替真实 QQ、实际模型调用、B站材料获取和 Mac 重启恢复的证据；运行结果应分别标明模拟通过与真实通过。

通过验证后，再固化适配边界和具体方案，按项目约定在 [GitHub Issues](https://github.com/FrigidCrow/dafeiyu/issues) 保存实施规格与开发任务。验证若暴露阻塞，应记录是哪项必要能力缺失、修补成本如何，再决定继续 DSH 还是评估 AstrBot，不能因为研究文档完整就视为可用。
